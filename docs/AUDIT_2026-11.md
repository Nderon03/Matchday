# Pre-rollout audit (November 2026)

Full audit before closed testing: security, payments, business logic, app robustness, compatibility.
Every fix ships **over the air to build v9** (native fingerprint verified identical), plus a database
push and one server-function deploy.

## Issues found and fixed

| # | Severity | Area | Issue | Fix |
|---|---|---|---|---|
| 1 | **High** | Security | Signed-out API callers (using the public website key) could run every database function. Postgres grants `PUBLIC` execute by default, so earlier `revoke … from anon` lines never took effect. | All functions revoked from `public`/`anon` (and by default for future ones); only `get_link_preview` and `is_username_available` stay open signed-out. Migration 72. |
| 2 | **High** | Security | `finalise_season` treated "no signed-in user" as the scheduler: anyone could end any group's season early and trigger its awards. | Trusts only real server calls (`called_by_system()`); admins otherwise. Migration 72 + tests. |
| 3 | **High** | Security | `create_session_from_template` did the same: a signed-out caller could create a game as any user by passing their id. | Same fix. Migration 72 + tests. |
| 4 | **High** | Payments | Stripe webhook stored an event as "seen" before processing it. If processing failed halfway, Stripe's retry was skipped as a duplicate, so a payment could stay unpaid after the money was taken. Database errors were also ignored. | Reprocess events that were never finished; surface errors so Stripe retries. `stripe-webhook` function. |
| 5 | Medium | Payments | Payout bookkeeping could record the same payout twice when an event is reprocessed. | Unique index (existing duplicates cleaned) + safe upsert. Migration 73. |
| 6 | **High** | App | A "removed from a game" notice with no details crashed **every screen** (the notice is app-wide). | Notifications always have a details object (also for older saved data). |
| 7 | Medium | App | Group screen/settings crashed if the group came back missing. | Loader raises a proper "not found". |
| 8 | Medium | App | Profile "Partners & rivals" crashed if that player's profile is hidden. | Only shown when the player is there. |
| 9 | Medium | App | Notification settings: spun forever if loading failed; crashed with no saved settings. | Error message with retry; safe defaults. |
| 10 | Medium | App | Dream Team could render a half-built team and crash. | No team instead of a broken one (+ unit test). |
| 11 | Low | App | Line-ups, results and payments crashed on missing lists; Home season card and several screens on missing names. | Game data always has its lists; `firstName()` helper for names. |
| 12 | Low | App | Data saved on devices by older versions stayed there after the format changed. | Removed on next launch and on sign-out. |
| 13 | Low | Website | Invite preview image URL wasn't HTML-escaped (server-generated, so not exploitable). | Escaped; XSS tests for game/group/friend previews. |
| 15 | Low | Payments | Payout bookkeeping recorded the host's amount minus the player's booking fee (e.g. £5.40 for a £6 game), though the host actually receives the full £6. Not shown in the app yet. Found by the payment rehearsal below. | Records the real amount. `stripe-webhook` function. |
| 14 | Low | Release | A `.gitignore` edit would have changed the native fingerprint and stopped the update reaching v9. | Reverted; fingerprint verified equal to v9. |

Fixed earlier in this release cycle (and covered by tests): hidden-profile black screen, error
safety net that couldn't draw, group deletion blocked by group-only games, sounds playing only once,
host hand-over.

## Checked and found sound
- Row-level security on every table; signed-out callers can read only `app_settings`.
- Every host/admin action checks permissions on the server (`require_session_manager`, `is_group_admin`).
- File storage: users write only to their own folder; group images only by admins.
- Stripe webhook signatures: verified with timestamp tolerance and constant-time comparison.
- Checkout: every amount is computed on the server; players can only pay their own bill.
- Cron/notification endpoints require a secret; the weather endpoint checks the caller can see the game.
- "I'm in" locks the game row, so two players can't take the last place at once.
- Live-update subscriptions and timers are cleaned up (no leaks); sign-out clears cached data.
- No secrets or keys committed.
